# 笔记与会话摘要

<!-- context:section id="goal" -->
有些材料从不存放在 Context 能读取的仓库或文档中：来自它无法访问的系统的摘录、一项决策的摘要、一线观察记录、经验总结出的检查清单，或你与 Agent 进行设计讨论得出的结论。把它保存为**笔记**或**会话摘要**。保存下来的文本本身就是页面所引用的证据，无需再做任何采集。

| 你的材料 | 保存为 |
| --- | --- |
| 你手头已有的文本：摘录、摘要、观察记录、检查清单 | 笔记 |
| Agent 对话中确定下来的内容：决策、约束、未决问题 | 会话摘要 |
| Context 能自行读取的文档 | 改用[文档目录](document-directories.md)或[飞书文档](lark-documents.md)来源 |
<!-- /context:section -->

<!-- context:section id="prepare" -->
## 笔记里放什么

笔记可以包含原文、精选的逐字摘录、摘要，或几者混合。没有固定模板要求，但如果同时包含原文和摘要，请用标题或文字把它们分开，并将摘要明确标注为摘要，而不是原始记录。

- 保留会影响结论的限定条件、例外、分歧和未决问题。
- 当省略内容很重要时，说明材料的出处以及略去了什么。
- 只引用真实的输入；不要编造链接、发言人、日期或确认信息。
- 笔记中出现某个链接，并不代表其目标已被读取。

页面按保存时的样子引用笔记，所以在保存之前，请删去最终读者不应看到的任何内容。
<!-- /context:section -->

<!-- context:section id="summary-what" -->
## 什么是会话摘要

与 Agent 进行的设计讨论、问题排查和需求对话，常常会确定一些没有任何文档记录的事情。会话摘要为这样的对话保留一份有边界的记述，供页面引用。它是摘要，绝不是对话记录：Context 不会扫描你的 Agent 历史，也不会收录整段对话。
<!-- /context:section -->

<!-- context:section id="summary-keep" -->
## 从对话中保留什么

由 Agent（或提供摘要的人）在保存前整理：

| 保留 | 舍弃 |
| --- | --- |
| 问题、已确认的决策及重要的理由 | 重复的对话轮次 |
| 约束和未决问题 | 工具日志 |
| 每条陈述处于提议、已同意、已实现还是已验证状态 | 已放弃的尝试，除非它们能解释当前的限制 |

如果只有别人提供的摘要，来源中会如实说明。发言人、日期和批准信息绝不编造；没有可复用内容的对话可以不放进知识工作区。
<!-- /context:section -->

<!-- context:section id="save" -->
## 保存笔记

用自然语言告诉 Agent：

```text
请把这些发布流程笔记保存为 Context 笔记，再用它们整理一篇关于热修复发布的页面。
```

Agent 会以带日期的名称保存笔记。仅保存不会启动任何知识工作；当你要求写页面时，Agent 会把该笔记加入该任务读取的来源，同时保留已有的来源。如果笔记只用于支撑某个已有页面，则无需这样做：在修订时它会被纳入该页面的阅读范围。
<!-- /context:section -->

<!-- context:section id="summary-save" -->
## 保存会话摘要

在对话结束时提出：

```text
请总结我们关于重试上限的决定，保存为 Context 会话摘要，并关联到我们刚刚创建的合并请求。
```

Agent 以实际的对话日期命名摘要，若未知则使用采集日期，之后的修正沿用同一名称。它可以把摘要关联到一个或多个代码变更，按提交、合并请求或两者关联；不涉及代码的讨论无需关联。关联只记录对应关系：它不能证明变更已合并或已测试，也不授权获取代码。
<!-- /context:section -->

<!-- context:section id="use" -->
## 保存的材料如何被使用

保存不会启动任何知识工作。开启新的读者主题的摘要会经过常规的规划、写作和审核；只用于支撑已有页面的摘要会被纳入该页面的阅读范围，页面仍保留其主要来源。无论哪种情况，知识都会把结论转化为回答、讲解和步骤，而不是会议纪要，Context 也会记录哪些章节引用了该摘要。

问答之后的完整流程见[从对话中采集](../updates-and-versions/capturing-from-conversations.md)。
<!-- /context:section -->

<!-- context:section id="writing" -->
## 笔记如何变成知识

Agent 会把有用的内容融入面向读者的讲解、规则或步骤中；它不会整篇照搬笔记，也不会把提议当成事实。只有在措辞本身很重要时，才会引用一小段原文。引用指向存储的笔记，绝不指向 Agent 无法读取的原始材料。
<!-- /context:section -->

<!-- context:section id="correct" -->
## 修正笔记

两类不同的问题，对应两种不同的修复方式：

| 问题 | 怎么提 |
| --- | --- |
| 笔记没有如实反映材料 | 让 Agent 修正笔记本身。 |
| 笔记无误，但某个页面有误导 | 让 Agent 只修订该页面；修订后会交回给你审核。 |

批准知识绝不会修改或删除笔记。如需重命名笔记，告诉 Agent：它会先向你展示变更，再更新对该笔记的引用。
<!-- /context:section -->

<!-- context:section id="summary-correct" -->
## 修正会话摘要

让 Agent 以同一名称保存修正后的版本。已关联的代码变更会被保留，除非你要求移除。如果摘要准确而某个页面有误，就修订页面。保存摘要和批准知识都不代表批准了其中提到的代码变更。
<!-- /context:section -->
