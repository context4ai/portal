# 版本、Changelog 与恢复

<!-- context:section id="goal" -->
知识工作区有自己的版本号，采用 SemVer 形式。每轮完成的工作都会记录**一个**新版本和一条简短的 Changelog 条目，知识包、网站和 LLM Docs 都会带上这个版本。中间批次和部分结果永远不会单独获得版本。
<!-- /context:section -->

<!-- context:section id="bump" -->
## 哪一位数字会变化

| 本轮的变化 | 递增 |
| --- | --- |
| 新增模块或扩大覆盖范围的材料 | Minor |
| 修正、对现有模块的更新、导航、持久状态 | Patch |
| 你明确称为主版本的任何变化 | Major，仅在你指示时 |

除非知识工作区已有更高的版本或你另行指定，第一个版本是 `0.1.0`。进行中的工作永远不会改变版本。
<!-- /context:section -->

<!-- context:section id="record" -->
## 如何记录

在一轮工作接近结束时——页面审核通过之后、最终构建之前——Agent 会查看实际发生的变化，包括文章正文、资源、结构、导航和模板，然后撰写 Changelog 条目：标题、主要变化以及引发它们的原因，例如新增模块、笔记、更新或修复。相关的变化会被合并，让每个条目保持简短。条目中绝不包含凭据、原始对话文本、本地路径或私有账号 ID；作者取自你的 Git 身份，而不是猜测。

版本号和 Changelog 会一起更新。记录版本本身不会发布或部署任何内容。背后用到的命令列在 [CLI 命令](../../product/reference/context/cli-commands.md)中。
<!-- /context:section -->

<!-- context:section id="retries" -->
## 重试与重新发布

构建失败时会复用已记录的版本，重试不会递增版本。如果构建失败后必须修改内容，仍可以修订尚未发布的版本。内容一旦发布，后续任何改动都需要更高的版本。仅在本地构建并不会封定版本。
<!-- /context:section -->

<!-- context:section id="readers" -->
## 读者在哪里查看

网站有一个历史页面：卡片按从新到旧排列，最新的三张展开，较早的折叠。主题切换旁的 History 按钮和页脚的更新时间都链接到该页面。知识包和 LLM Docs 带有相同的版本和 Changelog。
<!-- /context:section -->

<!-- context:section id="restore" -->
## 回到较早的版本

让 Agent 恢复某个版本：

```text
把知识恢复到上周五的状态。
```

它会弄清你指的是哪个已保存的状态，结束所有未完成的工作，并且只恢复知识工作区自己的文件以及该版本使用的来源。它从不重置仓库的其余部分，也不会找回临时的任务进度。当目标和受影响的文件都明确时，一个清楚的恢复请求无需再次批准；不明确时，Agent 会询问你。
<!-- /context:section -->

<!-- context:section id="target" -->
### “较早的版本”指什么

| 你说的 | 目标 |
| --- | --- |
| 没有具体说明 | 工作区上一次保存的状态——这会撤销尚未提交的结果 |
| “上一个版本” | 工作区的前一个已保存状态，而不只是大型仓库的上一个提交 |
| 某个提交 | 经检查后，恢复到该提交 |
| 某个日期 | 按你的时区和含义理解（例如截至当天结束时）；如果有多个状态都可能匹配，Agent 会与你确认 |

恢复之前，Agent 会向你展示将要发生的变化。此后新增的文件会被建议删除；无关文件、你已暂存的工作以及来源检出都会保留。移动和重命名也会被考虑在内。
<!-- /context:section -->

<!-- context:section id="restore-result" -->
### 你会得到什么

- 工作区文件恢复为目标时的样子，分支历史保持不变。
- 该版本使用的来源——仓库版本、文档快照和附件。丢失的旧快照绝不会用较新的远程内容代替，仍然可用的来源也不会重新拉取。
- 现有产出会被报告为已过时，直到你要求重新构建。恢复旧配置不会启动完整的重新索引；如果旧格式不兼容，Agent 会告诉你需要做出的选择，而不是悄悄重写页面。

随后，Agent 会对照目标检查恢复后的文件，并确认没有无关内容发生变化。如果某些来源无法恢复，它会报告部分结果，并说明缺少哪些访问权限或版本。恢复本身不会提交或推送；满意后请让 Agent 提交恢复后的状态——参见 [开始新任务与保存工作](../workspace-maintenance/preparing.md)。
<!-- /context:section -->
