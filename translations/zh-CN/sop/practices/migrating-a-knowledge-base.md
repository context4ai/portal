# 迁移已有知识库

<!-- context:section id="goal" -->
如果你手里已经有知识，比如 LLM 维护的 wiki、文档目录、另一个知识工作区或已发布的知识包，就不必从零开始。先创建知识工作区，说明已有哪些内容，再让 Agent 调研并规划迁移。正式写作之前，你会先审阅调研报告和 PLAN。

已有知识库的规模通常够得上分阶段计划，所以 Agent 会用 `context-plan` 来做：先确认你的目的和约束，逐个调研资料集，为每个资料集提出接入方式，再一个阶段一个阶段地推进，每个阶段都有自己的[确认开工报告](../planning-and-production/start-reports.md)。阶段怎么划分、怎么审核，见[分阶段规划大型项目](../planning-and-production/planning-large-projects.md)；第一批来源怎么接入，见[知识库冷启动](cold-start.md)。
<!-- /context:section -->

<!-- context:section id="prompt" -->
## 迁移提示词

工作区建好后，可以这样开始：

```text
先调研 Context 能做什么，再规划如何接入我们已有的知识：

- 知识现在放在哪里、由谁维护，以后是否还在原处维护：
- 目前怎么生产这些知识（脚本、提示词等）：
- 哪些内容的措辞必须保持不变，哪些结构不能改：
- 谁会阅读结果，不同读者是否需要各自的知识包：
- 历史问答或评测题集，用来说明这些知识平时怎么被使用

写一份调研报告，做到 PLAN 后暂停。方案和阶段划分由我来审阅。
```

知道多少答多少；“还没定”也可以，会记为待定事项。最后一项最重要：真实的问题能让 Agent 明白这些知识*拿来做什么*，之后也能直接当作评测题集。

## 调研会告诉你什么

对每个资料集，Agent 会弄清楚：

- **它属于哪一类**：别处文档的镜像加摘要、原始归档、根据代码写成的 wiki、团队自己维护的一手页面，还是已发布的知识包；以及由谁维护。
- **它真正的出处**：页面依据的是哪些文档和仓库，其中哪些工作区里已经有了，哪些内容只有这个资料集才有。
- **它准不准确**：在固定版本的代码上核对十条左右的具体说法，每条判为一致、部分一致、不一致或无法核实；有问题的再分成*写错*和*过时*两类。
- **它会带来哪些变化**：相关主题会放在导航的什么位置，和已有文章有哪些冲突，每个知识包会收录哪些文章。

调研报告开头就是结论：每个资料集的建议，收益和成本并排列出。分析、评分和证据放在后面。

## 为每个资料集选择接入方式

每个资料集（或资料集的每个部分）各自选择接入方式。Agent 会对照你的回答给每种方式打分，并在旁边列出可行性、工作量和风险：

| 方式 | 适用情况 | 原资料之后怎么办 |
| --- | --- | --- |
| 据此产出文章 | 知识需要为你的读者重写，并与代码核对；根据代码写成的 wiki 能告诉你哪些问题重要 | 工作区接手维护这个主题后即可归档 |
| 登记原始上游 | 资料集只是镜像或总结了别处的文档，可以直接登记那些文档；作者自己的判断整理成笔记 | 摘要部分可以不再维护 |
| 原样纳入页面 | 团队的页面必须保留原有措辞，但要放进你的目录并与代码核对。参见[原样纳入页面](../review-and-revision/keeping-pages-as-written.md) | 继续在原处维护 |
| 跟进已发布的版本 | 内容由其他团队按版本发布（文档仓库或知识包）。参见[按版本发布与即将归档的资料](../registering-sources/versioned-external-content.md) | 随发布方更新 |
| 留在原处 | 它服务的是在自己仓库里工作的 Agent，或者只需要一个链接 | 继续在原处维护 |

对每个资料集，你还要决定是**持续跟进**上游（按固定版本登记，由例行更新跟上新版本），还是**一次性吸收**（把文件作为保留文件夹结构的文档来源接入，作者的判断整理成笔记，原资料归档后冻结这个来源）。

知识包和导航互不依赖。知识包按路径或明确列出的清单挑选文章，所以不需要单独的顶层目录。只放在知识包里的内容，挂在知识地图的隐藏分组下：网站菜单里看不到，但知识包和 LLM Docs 里都有。参见[知识包](../outputs-and-sites/knowledge-packages.md)。

留在原处的资料也可以接入：

- **文档目录**：把已有文档所在的文件夹登记为来源，采集后引用其中的内容。参见[文档目录](../registering-sources/document-directories.md)。
- **同一仓库里的文档和 Skill**：已经在同一仓库中的文档和自己编写的 Skill 登记为仓库内容，原文件不动，Context 直接引用而不迁移。参见[链接已有的文档与 Skill](../registering-sources/same-repository-docs.md)。
- **外部入口**：页面只需要链接到别处的内容时，只做声明，不下载也不采集。参见[外部入口](../registering-sources/external-entrances.md)。

资料集里附带的 Skill、Agent 和脚本不属于知识，应通过 Agent 宿主的 Skill 分发渠道发布，不要打进知识包。

## 先评测，再切换

新知识库验证通过之前，旧知识库继续保留。用同一套题集分别测试两者，比较回答质量、耗时和工具调用次数，方法见[评测知识库效果](./evaluating-your-knowledge-base.md)。
