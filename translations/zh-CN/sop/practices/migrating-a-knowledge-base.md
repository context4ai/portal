# 迁移已有知识库

<!-- context:section id="goal" -->
如果你已经有知识——LLM 维护的 wiki、文档目录、另一个知识工作区或已发布的知识包——就不必从零开始。创建一个知识工作区，描述已有的内容，让 Agent 调研并规划迁移。在写任何内容之前，你会先审阅调研报告和 PLAN。

已有知识库通常会达到分阶段计划的门槛，因此 Agent 通过 `context-plan` 工作：它确定你的目的和约束，研究每个资料集，提出每个资料集的接入方式，然后逐个运行阶段，每个阶段都有自己的[确认开工报告](../planning-and-production/start-reports.md)。阶段如何划分和审核，参见[分阶段规划大型项目](../planning-and-production/planning-large-projects.md)；如何接入第一批来源，参见[知识库冷启动](cold-start.md)。
<!-- /context:section -->

<!-- context:section id="prompt" -->
## 迁移提示词

工作区建好后，从这里开始：

```text
先调研 Context 能做什么，再规划接入我们已有的知识：

- 知识现在在哪里、由谁维护，之后是否继续在原处维护：
- 目前如何生产（脚本、提示词等）：
- 必须保持措辞的内容，以及不能改变的结构：
- 谁来阅读结果，不同读者是否需要单独的知识包：
- 历史问答或评估题集，用来说明这些知识是怎么被使用的

写一份调研报告，继续到 PLAN 后暂停。我来审阅方案和阶段划分。
```

知道多少就答多少；“还没决定”也可以，会记录为待定决定。最后一项最重要：真实的问题会告诉 Agent 这些知识是*用来做什么的*，之后也会成为你的评估题集。

## 调研会告诉你什么

对于每个资料集，Agent 会弄清：

- **它是什么类型**——其他文档的镜像加摘要层、原始归档、根据代码写成的 wiki、团队维护的一手页面，还是已发布的知识包——以及由谁维护。
- **它真正来自哪里**——页面所依据的文档和仓库，其中哪些工作区已经有了，以及哪些内容是该资料集独有的。
- **它有多准确**——在固定版本的代码上核对大约十条具体说法，每条判定为一致、部分一致、不一致或无法核实，问题分为*写错*和*过时*两类。
- **它会带来哪些变化**——其主题在你的导航中的位置、与已有文章的冲突，以及每个知识包会包含哪些文章。

调研报告以结论开篇：每个资料集的建议，收益与成本并列。分析、评分和证据随后给出。

<!-- context:section id="sources" -->
## 选择每个资料集的接入方式

每个资料集，或资料集的每个部分，都有各自的接入方式，并对照你的回答打分，评分旁列出可行性、工作量和风险：

| 方式 | 适用情况 | 原资料之后如何 |
| --- | --- | --- |
| 基于它产出文章 | 知识需要为你的读者重写并与代码核对；根据代码写成的 wiki 会指出哪些问题重要 | 工作区接手维护该主题后可以归档 |
| 登记原始上游 | 资料集镜像或总结了你可以直接登记的文档；作者自己的判断转为笔记 | 摘要层可以不再维护 |
| 保持页面原文 | 团队的页面必须保持措辞，但要放进你的分区并与代码核对。参见[保持页面原文](../review-and-revision/keeping-pages-as-written.md) | 继续在原处维护 |
| 跟随已发布版本 | 其他团队按版本发布内容（文档仓库或知识包）。参见[按版本发布与即将归档的资料](../registering-sources/versioned-external-content.md) | 跟随发布方 |
| 留在原处 | 它服务于在自身仓库中工作的 Agent，或只需要一个链接 | 继续在原处维护 |

对于每个资料集，你还要在**跟随**上游——以固定版本登记，由例行更新持续跟进——和**一次性吸收**之间选择：文件作为保留文件夹的文档来源接入，作者的判断转为笔记，原资料归档时冻结该来源。

知识包与导航相互独立。知识包按路径或显式列表选择文章，因此不需要自己的顶层分区。只属于知识包的内容放在知识地图的隐藏分组下：它不出现在网站菜单中，但保留在知识包和 LLM Docs 里。参见[知识包](../outputs-and-sites/knowledge-packages.md)。

留在原处的材料仍然可以接入：

- **文档目录**——把一个已有文档的文件夹登记为来源，采集并引用其内容。参见[文档目录](../registering-sources/document-directories.md)。
- **同仓库的文档与 Skill**——已经放在同一仓库中的文档和自编写的 Skill 登记为仓库内容；原文件留在原处，Context 引用它们而不是迁移它们。参见[链接已有的文档与 Skill](../registering-sources/same-repository-docs.md)。
- **外部入口**——页面需要链接到的其他地方的内容，只声明而不下载或采集。参见[外部入口](../registering-sources/external-entrances.md)。

资料集附带的 Skill、Agent 和脚本不是知识；请通过 Agent 宿主的 Skill 分发渠道发布它们，而不是打进知识包。

## 测量之后再切换

在新知识库得到验证之前，保持旧知识库继续运行。用同一套题集分别测试两者，比较质量、耗时和工具调用次数，方法见 [评测知识库效果](./evaluating-your-knowledge-base.md)。
