# 知识服务 Agent 设计（脱敏）

本笔记是 Portal 文档站指南“知识服务 Agent”分组的来源，整理自团队把 Context 技能接入团队聊天 Bot 的运行经验，以及本站后续提供站内 Bot 的设计假设。不包含内部平台、账号、链接或业务数据。

社区版尚未提供 Bot 实现，下文的运行环境与服务接口是规划；技能、流程与交互经验已在实际运行中验证。

## 定位

知识服务 Agent 是一个常驻的 Agent：它用 Context 技能生产、更新和检索知识，人在关键决策点审核。它不是新的 Agent 平台，而是给已有的 Agent 运行环境装上 Context 技能插件、Bot 提示词和远程检索。

同一套技能与平台无关：可以运行在托管 Agent 环境里，也可以运行在 Claude Code、Codex、Cursor 等本地编码 Agent 中。常驻 Bot 适合团队共享的知识：生产中需要大量搜寻资料和交互确认，问答需要随时可用。小模块的知识随仓库放在 `docs/` 中也合适。

## 运行时架构

本站的 Bot 计划采用托管 Agent 运行环境加 API 搭建：

| 层 | 组成 | 职责 |
| --- | --- | --- |
| 入口 | 网站对话、团队聊天 Bot、定时任务、API 调用 | 提问、提出生产或更新要求、例行巡检 |
| 服务层 | 会话 API | 鉴权、限流、为每个会话创建运行环境、转发事件流、把结果渲染为网页消息或聊天卡片、收集评价 |
| Agent | 托管 Agent 运行环境 | 每个会话一个隔离沙箱；系统提示加 Bot 提示词，按意图选择技能 |
| 技能 | Context 技能插件 | 生产：`context`、`context-plan`、四个 Indexer；检索：`context-inspect-search`；同仓库文档：`context-repo-content` |
| 底层能力 | `context` CLI 与 Agent Graph、Source Graph MCP、Git | 工作流推进与恢复、按 commit 远程读取代码、提交知识工作区 |
| 出口 | 知识仓库（Git）、知识包、知识网站 | 构建后一次发布到三处 |

运行环境首选 DeepSeek Harness（DSH），也可以换用等价的托管 Agent 环境，如 E2B、Daytona、Modal、Cloudflare Sandbox、Fly Machines；选型看沙箱启动时间、会话时长上限、文件系统持久化与出网控制。服务层只依赖“创建会话、发送消息、读取事件流、结束会话”这类通用接口，换运行环境时不改技能。

## 三条流程

| 流程 | 步骤与技能 |
| --- | --- |
| 生产 | 环境准备（恢复工作区与来源版本，`context`）→ 分析规划（Bot 提示词识别意图，`context-plan`）→ 采集（代码固定到 commit，文档保存快照，`context`）→ 写作（Indexer 技能，每段附原文引用）→ 审核（自动校验引用，人审 Diff 报告）→ 构建发布 → 归档（版本与 Changelog） |
| 检索 | 环境准备（挂载插件与知识包）→ 分析规划（识别问答意图）→ 查找知识（`context-inspect-search`，先读索引再读正文和证据）→ 知识不够时深度探查（Source Graph 按 commit 读原文）→ 结论在前、附出处作答 |
| 更新 | 三种触发：对话中按新版本更新、检索发现缺口并经用户确认、定时巡检发现来源变化 → 评估影响（对比来源新旧版本，找出受影响文章）→ 只修订受影响部分并同步引用 → 人审 Diff 报告 → 发布 → 回执变更文章与新版本号 |

## 交互经验

- 回复分为开始、进度、最终结果三类消息，同一任务更新同一条进度，不要一次发出很多条。
- 只有需要用户决定时才提问（开工报告确认、发布确认、范围取舍），用可点选的选项，不让用户回复暗号或审核码。
- 用户在网站上审完 Diff 报告后直接推进后续流程，不必回到聊天里确认。
- 维护者不需要关心知识仓库提交、知识包与站点发布的细节；默认静默完成，只在 Diff 审核、权限问题或有异议时打断。
- 答案附可点击的出处：知识页、代码行（带 commit）与原始文档；只说“依据知识包”太抽象。
- 回答下方提供赞、踩评价，评价与会话一起用于改进检索和提示词。

## 边聊边沉淀与定时巡检

- 问答结束后，用户觉得结论值得保留，可以直接要求沉淀：聊天内容、新给的文档、指定的代码或 MR 都可以作为来源，Agent 先给规划，再走更新流程。
- 可以指定全仓或部分范围触发更新；Agent 分析上次更新以来上游文档与代码的变化，先给更新计划，再给基于网站基线的 Diff 报告。
- 定时任务按固定时间触发巡检，跟踪上游文档与代码变化并沉淀知识；巡检提示词要写明范围、无变化时的处理与需要人确认的情形。

## 运维知识

- 配合命令行工具的运维技能可以写成知识文章，之后经 Agent 对话直接使用。
- 需要的环境变量在 Agent 运行环境中配置，知识里只写变量名，不写取值。

## 性能经验

- 冷启动是首次问答慢的主因：运行环境预置 CLI、知识包与知识工作区，可以省去每次安装与克隆。
- 先读知识，证据不够再远程读原文；用 Source Graph 按 commit 读取代码，不在沙箱里克隆仓库。数字见测评汇总笔记。
- 简单问题仍有优化空间，目标是一分钟内答复。

## 本站 Bot 的边界

- 公开访客只能问答；生产、更新与发布只对维护者开放，由服务层鉴权。
- 只读取已登记的公开来源；凭据只在服务端，不进入知识、提示词或回复。
- 社区版不依赖任何内部平台；聊天平台接入优先使用长连接事件订阅，无需公网回调地址。
